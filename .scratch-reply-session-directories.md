# Reply — `session_theories` ignores the ROOT `directories` clause

**Status: fixed, in `isabelle-layout` git, unreleased.** The diagnosis was
exact and the fix landed essentially as proposed. One part of it was
**declined**, with evidence below, because it would have reintroduced the same
class of bug in a rarer shape.

Both of your reproductions now pass against the current tree:

```
synthetic fixture   ['A', 'B', 'T']                    (was ['A', 'T'])
AFP fixture         Refine_Dflt_No_Comp    discovered
                    Refine_Intersection    discovered
                    GenCF_No_Comp          discovered
```

AFP load set 9,907 → **9,910**, 0 lost — matching your simulation exactly.

---

## The one change not taken: the ROOT-directory confinement

Your patch guarded the widened index:

```python
if extra.is_relative_to(root_dir):
    search.append(extra)
```

reasoning that it mirrors the containment `_classify_import` applies to
relative-path imports, and stops a malformed ROOT pulling in a sibling entry.
The shipped fix has **no such guard**. Isabelle was asked directly rather than
inferred from, and it disagrees with the guard twice over.

### 1. Isabelle does not confine the clause, and a confined reader loses theories

`Pure/Build/sessions.scala:725` — `def dirs: List[Path] = dir :: directories`.
No containment. Put to the prover:

```
escape2/EntryA/ROOT      session A in "Sub" = HOL +
                           directories "../../Shared"
                           theories T
escape2/EntryA/Sub/T.thy theory T imports Neighbour begin end
escape2/Shared/Neighbour.thy
```

```
$ isabelle build -n -d /tmp/escape2 A
0:00:02 elapsed time                    # accepted, and builds
```

With the guard, `Neighbour` is dropped from the load set — a legal ROOT, a
silently short answer, the reported bug in a different shape. Without it, we
return `['Neighbour', 'T']`.

### 2. The corpus the guard defends against is one Isabelle refuses

The double-claim worry is real but it is Isabelle's to police, and it does.
`sessions.scala:901–913` builds a canonical-directory → session map across the
whole selection and errors on collision:

```
$ isabelle build -n -d /tmp/escape A
*** Duplicate use of directory "/private/tmp/escape/EntryB"
***   for session "A" (line 1 of ".../EntryA/ROOT")
***   vs. session "B" (line 1 of ".../EntryB/ROOT")
```

So no legal corpus can contain the shape. Guarding against it costs real
theories in legal ROOTs and buys nothing in illegal ones — where, having no
ground truth, we prefer to be permissive rather than to invent a silent
exclusion.

Pinned by `test_a_directories_entry_may_leave_the_root_directory`, whose
docstring carries this reasoning, so it cannot be "fixed" back later.

## A second fault, found by your own suggestion

You wrote that the closure invariant was *"worth having somewhere
permanent"*. Adopted — `scripts/probe_discovery_closure.py` — and on its first
run after your fix it found an unrelated hole in the same function.

`_INFRA_ROOTS` was consulted **before** the filesystem, so a bare import
matching a hardcoded distribution name returned `infra` without checking
whether the session owned a file of that name. `src/CCL` is a session called
`CCL` whose `Term.thy` imports `CCL`, meaning `CCL/CCL.thy`. Six theories
across `CCL`, `Cube` and `Sequents` were lost.

Fixed by deleting the short-circuit: a bare name that resolves to a file the
session owns *is* that file, whatever it is called. The name list still governs
qualified imports, where there is no local file to check.

Measured first, because it moves a classification your census depends on:
across both corpora exactly 12 sessions hold a theory named like a distribution
logic — 11 the object logic defining itself (`ZF/ZF.thy`), the twelfth an AFP
entry with its own `Sequents.thy`. **AFP load set unchanged at 9,910**;
distribution +6; nothing lost. So no AFP census number moves on account of this
one.

## What this prompted: a stronger oracle

The closure invariant needs no prover, which is its virtue — but a load set
that is uniformly too small satisfies it perfectly. `isabelle build -n -l`
lists the source files a session build actually reads, so it checks the
*value*, not just an invariant. `scripts/probe_against_isabelle.py` now does
that comparison.

The two sides answer slightly different questions — `isabelle build -l` lists
every source the build reads, including other sessions' theories, while
`session_theories` excludes cross-entry imports so each entry contributes its
own theories exactly once. So the comparison is asymmetric:

| | must be | Isabelle2025-2 |
|---|---|---|
| we return a file the build does not read | 0 | **0** AFP, **0** distribution |
| build reads a file we omit, **inside** the session's own dirs | 0 | **0** AFP, **0** distribution |
| build reads a file we omit, outside them (another session's) | any | 10,850 AFP, 471 distribution |

988 AFP sessions and 132 distribution sessions, exact agreement. If it is
useful downstream, the probe takes a corpus argument and exits nonzero on
disagreement.

One trap worth passing on, since it produced a *plausible* wrong answer rather
than an error: a listing block header may carry a group — `Session HOL/HOL
(main)`, `Session Doc/Intro (doc)`. A parser anchored at end-of-line after the
session name skips those headers and attributes their files to the previous
session, yielding a confident report that `HOL-Lattice` is missing 394
theories from `Doc/Codegen`.
